# Assumption register

Every value in the port that is not yet taken from the original game, with the
lead for replacing it. Engine addresses are in the 3dfx edition (MW2.DLL); the
DOS MW2.EXE has the same simulation. Status: **assumed** (my number),
**inferred** (fits the data, mechanism not traced), **engine** (taken from code).

## 1. Movement and controls (tools/glview.c, src/mech3d.c, src/msim.c)

### Engine findings so far (3dfx MW2.DLL)
- Object classes: table at `0x1024c330`, 32-byte entries. Mech-like classes (1, 2, 4, 5, 6, 8)
  share: init `0x1001b120` (not decompiled; calls `0x1001b200`), reset `0x100190d0`,
  `0x10019310` (26 KB, likely physics), controller update `0x1001a180`, `0x1001adf0`.
- Object: input block at +0x4c (player: `0x10159e50`; AI: object+0x1aa), controller at +0x20.
- Input block: +4 torso twist demand, +8 throttle, +0xc turn axis, +0x10 second axis,
  +0x30.. per-action flags. Action table `0x10257c38` area: 5-byte entries {id, name ptr};
  handler `0x10037880` uses case = id + 1.
- Throttle presets: 10 steps (STOP, 2..9, FULL); input +8 = step / 576 (FULL = 1/64).
- Controller (c[n] = 32-bit field n):
  - c[0x12] throttle target = 1/64 + input+8 x c[0x2c]; c[0x2c] = 1.0 for every mech (reset).
  - c[0x13] follows c[0x12]; speed c[10] = (c[0x13] - 1/64) x c[0x22]; reverse x -0.5.
  - c[0x22] per-mech speed factor = MEK walk MP x 105.4945 (loadout applier `0x10041410`,
    store at `0x10041ac5`), then divided at reset by `DAT_1024a98c` = `DAT_1024a988` x 33.7838,
    which is 1.0 at the default 0.0296 s tick (~33.8 Hz): a frame-time normaliser.
    Full throttle: c[10] = walk MP x 105.49 / 64 = walk MP x 1.648 per base tick. How c[10]
    becomes ground motion is NOT YET TRACED (taken as units/tick it is only ~10 km/h for a
    Timber Wolf, so it is probably not a plain velocity; it may drive the walk animation). (superseded: see "Speed per walking MP" row below: 182 Hz ticks, walk MP x 300 cm/s)
  - twist c[2] = input+4, clamped to +-c[0x38] (per-mech limit). SOURCE NOT YET FOUND. (superseded: see "Torso twist limit / rate" row below (MGEO angle -> c[0x38]))
  - leg turn rate c[0xe] = (input+0xc / 1024 x 90) x cos(min(80, c[0xb] x 6.516) deg).
  - FEET_TO_TORSO (case 0x11): legs turn at a fixed +-55 to meet the torso.
- Loadout applier `0x10041410` also sets: c[0x39] (+0xe4) = tonnage (MEK +0); c[0x2a] (+0xa8)
  = MEK +0x10; c[0x32] (+0xc8) = MEK +0x14; c[0x31] (+0xc4) = jump MP (MEK +8);
  c[0x30] (+0xc0) = 0x712 if jump jets fitted (-2 / -1 otherwise); c[0x3b] (+0xec) =
  "jet ddy" = jump MP / (stack value, probably tonnage) x 0.1184 (debug print label).
- Heat sinking (engine): c[0x27] (+0x9c) = MEK heat_sinking (+0xc) x factor:
  AI mechs 0.000763 (mission temperature < -30: 0.00153, > 50: 0.000687);
  player by difficulty (`DAT_1024ac6c`+5): 0 -> 0.00107 (cold 0.00214); 1 -> 0.000763
  (cold 0.00153, hot 0.000687); 2 -> 0.000687 (cold 0.00103, hot 0.000549).
  Temperature `DAT_1024a9a8` comes from the mission. How c[0x27] is applied per tick (it
  also appears in c[0x25] += (c[0x13] - 1/64) x c[0x27] x 6.4) is NOT YET TRACED. (superseded: see §2 heat model and §20 "Walking heat" (once per frame))
- Speed readout (`0x10018470`, "%d kph"): prints |c[0x3d..0x3f]| (controller +0xf4/f8/fc),
  negated when c[0xb] (+0x2c) < 0. That vector is the velocity, IN KM/H.
- Physics `0x10019310`: velocity integrates an acceleration, v += a x dt, and the move is
  (v + a x dt / 2) x dt handed to the move/collide routine `0x1000b5e0`; dt is an integer
  elapsed time. Branch read so far is the airborne/jump-jet one (uses "jet ddy" c[0x3b]
  and the strafe/flags at input +0x1e..+0x21). The grounded branch that turns throttle
  speed c[10] into acceleration is lines ~140-296 of the decompile, NOT YET READ. (superseded: see §18 "Top speed vs gravity", "Contact radius / climb", "Directional jet drag" (0x10019310 read); the speed response itself is still open, see the "Throttle model" row)
- Elapsed time `DAT_1024ab4c` = game clock `DAT_1024ab44` delta per frame (`0x10008103`),
  x8 or /4 in debug time-scale modes; clock fed from timeGetTime / QueryPerformanceCounter.
  Its unit (ms or a game tick) is NOT YET PINNED - it decides km/h <-> world units. (superseded: see "Speed per walking MP" row (Miles timer 182 Hz))
- Alternative if static tracing stalls: run the DOS game in DOSBox with its debugger and
  read the controller fields live (top speed per mech, twist limit, heat).
- Next: c[0x38] twist limit writer (not in the loadout applier; candidates: stores at
  `0x100275e1`, `0x10027a7a`, `0x1002f77e`, or set from the HUD/MGEO records); how c[10]
  moves the mech (physics `0x10019310`, 26 KB, or the animation duration at object +0x94);
  tick unit `DAT_1024ab4c`. (done: all three leads resolved in the rows below and §18)

## 2. Combat (src/combat.c, src/combat.h)

### Engine findings (3dfx MW2.DLL)
- Heat model `0x10015f50`, every frame per mech: heat c[0x26] += c[0x25] (heat added this
  frame) - c[0x27] (dissipation per tick, from `0x10041410`) x elapsed ticks, x2 while shut
  down (state 3); never below 0. Thresholds (float): > 65 "Heat level critical" (message 0,
  voice 75) while rising; > 80 automatic shutdown (message 1, voice 78) unless overridden;
  restart when < 65 and >= 724 ticks (~4 s) shut down; > 100 not overridden for 4525 ticks
  (~25 s) -> `0x10016280` = mech destroyed (kill table +1); > 100 overridden -> random ammo
  explosion ("BlowAmmo", `0x10015e10`).
- Message table `0x1024f144`: 12-byte entries {text, 0, voice sample}; shown by `0x10031870`
  (message number in ecx).
- The simulation has its own weapon table: `.data 0x1025a6d0`, 0x58-byte entries, extracted
  to src/wtable.h. Fire routine `0x100437a0`: ready when clock - last >= refire (+0x34);
  while firing, every `interval` (+0x38) ticks adds `heat` (+0x24) to c[0x25].
  Projectiles per volley at +0x0c. Damage is not in this table: next to find (projectile /
  hit code), along with the meaning of interval for beams vs. volleys, and ammo use.

## 3. AI and mission logic (src/msim.c, src/mtbl.c)

### Engine findings: the AI is a data-driven rule system
- Order dispatch `0x10014520` -> `0x10014700(order, behaviour, leader?)`: per object class 1-8,
  index tables (`0x1024baa8`, `0x1024bb68`, `0x1024bae8`, `0x1024bba8`, `0x1024bbe8`,
  `0x1024bb28`) pick an AI program for leader / follower; the program pointer is stored at
  object +0x11c (3 slots).
- Programs = the 9 AIT resources (DEFLT, F/L x DEFEND, DESTROY, LEAVE, RECON), loaded by
  `0x100141a0` into `0x101e8844[]`.
- Program layout: u16 count, count x {u16 situation code, u16 value} (searched by
  `0x10013d90`), then 12-byte rules starting with u16 action; recurring condition codes
  0x40, 0x42, 0x22, 0x25 with parameters such as range code -2 / -4 (the stored AI ranges,
  see GPS "250") or distances (250, 300, 350, 500, 1000).
  e.g. DESTROY / DEFEND programs: `07 00 01 42 fe ff 04 ...` (action 7, condition 0x42, range -2).
- AI states (debug table `0x1024b5d0`): 0 idle, 1 avoid, 2 target, 3 attack, 4 flee, 5 follow,
  6 recon, 7 patrol, 8 godirect, 10 rest, 11 shutdown, 12 dead. State set by `0x10013e00` ->
  `0x10013790` (object +0x14a), only if the program lists that state (`0x10013d90`).
- Program header = (state, rule count) pairs; rules follow, grouped by state in header order
  (DEFLT: 14 rules x 12 = 168 bytes, exact). Rule collector `0x10011e40` gathers the current
  state's rules from the 3 program slots (slot 2 first, duplicates dropped) into object +0x118.
- Rule (12 bytes): u16 condition (0-7, table `0x1024bc70`: 1 `0x10012b40`, 2 `0x10012bf0`
  target choice by range, 3 `0x10012a80`, 4 `0x10012a60`, 5 `0x10012a70`, 6 `0x10013090`,
  7 `0x10012fd0` range check with stored ranges -2/-1), then condition params (flag byte,
  operator byte, i16 range/distance); byte 6 = action (table `0x1024bc90`: 0 `0x100132a0`,
  1 `0x100132b0`, 2 `0x100132c0`, 3 `0x10013320`, 4 `0x100141e0`); byte 7 = new state;
  bytes 8-11 more params. Evaluator `0x10011d20`: first rule whose condition and action both
  succeed changes the state.
  e.g. DEFLT patrol: `07 00 01 42 fe ff 02 02 ..` = if condition 7 (range -2) then action 2,
  state -> target.
- Lancemate commands (`0x10014390`) use the same state numbers: 2 attack my target, 5 form on
  me, 7 (attack variant), 8 go to nav, 11 hold.
- Target references (16-bit): 0x01xx nav point, 0x02xx object, 0x04xx group; selectors
  0x2100 current nav, 0x2101 assigned nav (+0x16a), 0x2200 the player, 0x2201 my leader,
  0x2202 self, 0x4200 iterate enemies (`0x10013a50`). Range of a reference (`0x10013450`):
  nav point radius, objects/groups 100 m (10000 cm), minimum 1 m.
- Rule bytes 2-3 = condition target reference (e.g. 0x4201 enemies), 4-5 = range/distance
  (-2/-1 stored AI ranges, -3 unlimited, else metres), 6 = action, 7 = new state, 8-11 =
  further reference (e.g. bytes 9-10 0x2201 my leader in DEFLT follow).
- Conditions (return a target reference, 0 = false): 1 nearest enemy within range (`0x10012b40`);
  2 highest-scoring target (`0x10012bf0`, score = targeting code `0x1001d510` > 0);
  3 nearest enemy within the reference's range (`0x10012a80`, + bookkeeping); 4 passes the
  current target (always true); 5 always false - fires only on a posted event (object +0x144 =
  condition, +0x146 = target; how commands/orders cut in); 6 `0x10013090` state/visibility
  flag check on the target (`0x10013c40`, flag 2); 7 range check vs stored ranges
  (`0x10012fd0` -> `0x10012de0`).
- Actions (non-zero = commit the state change): 0 always; 1 clears counter +0x140; 2 saves
  (state, target) to +0x128 for return, counts in +0x140; 3 succeeds when +0x140 == 0;
  4 alerts the group leader (`0x10014270`) and returns 0 (never changes state itself).
- Per-state movement `0x100130f0` (implemented in src/ai.c): target -> steer to target, throttle
  by distance (`0x100134c0`); flee -> full throttle; follow/recon/patrol/godirect -> waypoint
  (`0x10014ff0` torso sweep), distance throttle, steering (`0x10013600`); else 80% throttle in mode 2.
- Firing (`0x100231a0`, implemented): fire only within +-10 deg of the aim line, at intervals of
  rand(GPS skill + 1) x 22 ticks (+0x158), extra rand(3) gate for non-player targets; torso
  twist input written directly each frame (instant within the MGEO limit).
- Events (`0x10014270`, implemented): action 4 posts (rule condition, current target) to the
  group leader if none pending; the evaluator then fires the matching rule without its condition.
- GPS per spawn (implemented): payload +8 skill, +10/+12/+14 ranges for codes -4/-1/-2 (0 -> 250 m);
  payload +16 pilot level 1-4 (+0x159) sets manoeuvre capability flags (+0x19e) in `0x1001ee30`:
  bit0/bit1 level<4, bit2 <3, bit3 mech and <6, bit4 <5, bit5 mech and <2, bit6 <6 (lower = better).
- Attack manoeuvres (`0x1001ea40`, +0x170): 13 manoeuvres, chosen by `0x1001f030` as a Markov
  chain over static tables (mechs `0x1024cdf0`, alternative `0x1024cf28`; other classes fixed
  rows `0x1024cef8` = 12, `0x1024cf10` = 1, `0x1024cee0` = 0): row = (manoeuvre, n, next options),
  next = options[rand(n)]; overrides: 4 needs conditions and twist, 3 -> 2 if twist limit < 10,
  5 skipped in one case. Manoeuvre functions: 0 `0x1001f950`, 1 `0x1001f9d0` (moves to points
  ~150 m, every 543 ticks), 2 `0x1001faf0`, 3 weave (+-450 turn, flip every 543 ticks;
  IMPLEMENTED as the attack movement), 4 `0x1001fdd0`, 5 `0x1001fe30`, 6 `0x1001fb90`,
  7 `0x1001fc40`, 8 `0x1001fc00`, 9 `0x1001fcc0`, 10 `0x1001ff70`, 11 `0x1001fe10`, 12 `0x1001ffd0`.
- Manoeuvres (implemented in src/ai.c): 0 close to 150 m, ends < 45 m (forces 10) or after
  rand*181+1448 ticks; 1 move near the target (40 m), 3620 ticks; 2 close to 55 m, ends at
  max(1, km/h x 0.12987) x 80 m; 3 = 2 + weave; 6 charge at full throttle, ends < 20 m;
  7 close to 30 m, ends < 30 m; 8 full speed (ends on contact); 10 full speed; 11 hold and aim;
  12 approach to 30 m (vehicles); 4/5/9 jump-jet manoeuvres. Every manoeuvre aims the torso and
  runs the fire decision; general limit 9050 ticks. Aim is at the target's current position
  (`0x10013be0`): the engine does not lead.
- (older note) the per-state behaviour
  (`0x10013680` state setup, `0x10012730` / `0x10012150` per-state movement), then implement
  the interpreter in src/ai.c and replace msim.c's steering.
